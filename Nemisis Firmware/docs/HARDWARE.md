# Hardware

- **MCU:** STM32G474RET6 (Cortex-M4F, 170 MHz, 512 KB Flash, 128 KB RAM)
- **Board:** custom Nemisis micromouse PCB
- **System clock:** 160 MHz from HSE + PLL (`SystemClock_Config()` in `main.c`),
  VOS1 boost, Flash latency 4.
- **HSE crystal: 24 MHz.** `HSE_VALUE` must match the real crystal or every
  clock-derived value (`SystemCoreClock`, `SysTick`, `HAL_Delay`, the buzzer
  tone timing) is wrong.
  - PLL for 160 MHz: `HSE 24 MHz ÷ PLLM(3) × PLLN(40) ÷ PLLR(2) = 160 MHz`
    (PLL input 8 MHz, VCO = 320 MHz, both within range).
  - **Gotcha:** we build against the `nucleo_g474re` board id, but a real Nucleo
    sources its 8 MHz HSE from the ST-Link MCO, so the framework injects
    `HSE_VALUE=8000000`. That made `SystemCoreClock` compute to
    `8M ÷3 ×40 ÷2 = 53,333,320 Hz` even though the silicon (driven by the real
    24 MHz crystal) was actually running at 160 MHz. Fix: force the real value in
    `platformio.ini` → `build_flags = -D HSE_VALUE=24000000`. If RTT ever shows
    ~53.3 MHz again, this flag is missing/wrong.

## Pin map

| Signal       | Pin  | Peripheral / mode            | Notes                                   |
|--------------|------|------------------------------|-----------------------------------------|
| Buzzer       | PB8  | GPIO output (push-pull)      | Passive buzzer via MOSFET driver        |
| RGB LED data | PA2  | TIM15_CH1 (AF9), DMA1_Ch1    | 4× WS2812B `XL-1010RGBC-2812B` in chain |

Pin macros are defined in `Core/Inc/main.h`:

```c
#define BUZZER_Pin        GPIO_PIN_8
#define BUZZER_GPIO_Port  GPIOB
#define RGB_LED_Pin       GPIO_PIN_2
#define RGB_LED_GPIO_Port GPIOA
```

## TIM15 (WS2812 bit-stream generator)

TIM15 drives PA2 in PWM mode and is fed by DMA — one PWM pulse per data bit.

| Setting       | Value | Result                                            |
|---------------|-------|---------------------------------------------------|
| Timer clock   | —     | 160 MHz (APB2, prescaler ÷1 → timer ×1)           |
| Prescaler     | 1 (÷2)| 80 MHz counter clock                              |
| Period (ARR)  | 99    | 80 MHz / 100 = **800 kHz** PWM, 1.25 µs per bit   |
| DMA           | DMA1_Channel1, request `TIM15_CH1`, mem→periph, **half-word**, NORMAL mode |
| DMA IRQ       | `DMA1_Channel1_IRQHandler` → `HAL_DMA_IRQHandler(&hdma_tim15_ch1)` |

800 kHz (1.25 µs bit) is the WS2812B nominal bit rate. The `ws2812` driver derives
the "0"/"1" high-times from the ARR value (≈34 % / 66 % duty), so the timing
stays correct if the ARR is changed in CubeMX.

## Passive buzzer (PB8)

A passive buzzer has no internal oscillator, so a tone is generated by toggling
PB8 with a square wave at the desired frequency. Timing uses the **DWT cycle
counter** for microsecond accuracy (`HAL_Delay` is millisecond-only and far too
coarse for audible frequencies). See the `buzzer` library.
